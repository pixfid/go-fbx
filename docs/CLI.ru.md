# Справочник CLI

Точка входа: `go run ./cmd/fbx` (или собранный `./cmd/fbx`).

## Список команд
- `convert-zip` — импорт ZIP в FBX.
- `pack` — пересборка контейнера только из живых записей.
- `pack-many` — параллельная перепаковка набора FBX-файлов.
- `add` / `upsert` / `replace` — запись одного файла в контейнер.
- `rm` / `find` — фильтрация и удаление по пути и размерам.
- `stat` / `info` / `list` — инспекция контейнера и записей.
- `set-meta` — перепись записи с новыми метаданными.
- `replace-text` — массовая замена байтовой строки в подходящих записях.
- `extract` — потоковая выгрузка одной записи.
- `verify` — проверка целостности.

## Общая семантика
- Коды выхода:
  - `0` успех
  - `1` ошибка выполнения/данных
  - `2` ошибка аргументов/использования CLI
- Пути внутри контейнера нормализуются к `/` и должны соответствовать правилам FBX.
- Все размеры в флагах задаются в байтах.
- `--max-entry-size` и `--max-chunk-size` — лимиты безопасности (`0` = без лимита).
- Значения `--codec`: `store|zstd|lz4`.
- Значение `--level` по умолчанию: `0`:
  - для `zstd` это быстрый режим (не zstd default level 3)
  - для `store` игнорируется
  - для `lz4`: `0` = fast, `1..9` = HC-профиль с большим сжатием (значения выше `9` трактуются как `9`)
- Прогресс перерисовывается в одну строку: `[done/total] ▓▓▓...`.

## `convert-zip`
Синтаксис:
```bash
fbx convert-zip [flags] <input.zip> <output.fbx>
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--meta auto\|none` | `auto` | `auto` пишет авто-метаданные по ZIP entry; `none` отключает автогенерацию. | Уменьшить контейнер или сохранить происхождение данных. |
| `--meta-file <file.json>` | `""` | JSON map `path -> metadata object`; накладывается поверх авто-метаданных. | Подмешать свои ID/названия/служебные поля. |
| `--prefix <p>` | `""` | Добавляет префикс к путям внутри FBX. | Импортировать под `books/`, `images/` и т.п. |
| `--codec store\|zstd\|lz4` | `store` | Кодек для новых чанков. | Выбрать компрессию/скорость. |
| `--level <n>` | `0` | Уровень сжатия для writer. | Настроить zstd или lz4 HC по скорости/степени сжатия. |
| `--progress` | `true` | Показывает однострочный progress bar. | Видеть прогресс долгого импорта. |
| `--overwrite` | `false` | Разрешает перезапись выходного файла. | Контролируемая перезапись в скриптах. |
| `--max-entry-size <bytes>` | `0` | Отклоняет слишком большие entries при чтении/записи. | Защита от недоверенных ZIP. |
| `--max-chunk-size <bytes>` | `0` | Ограничивает/проверяет размеры чанков. | Защита от oversized chunk. |

## `pack`
Синтаксис:
```bash
fbx pack [flags] <input.fbx>
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `-o <output.fbx>` | in-place | Путь вывода. Если не указан — перепись входного файла через temp+rename. | Оставить исходник или уплотнить на месте. |
| `--codec store\|zstd\|lz4` | `store` | Переписывает все живые записи выбранным кодеком. | Сменить кодек контейнера целиком. |
| `--level <n>` | `0` | Уровень сжатия при перепаковке. | Контроль ratio/speed для zstd/lz4. |
| `--chunk-text <bytes>` | `0` | Переопределяет размер чанка для текста. | Оптимизировать чтение текстовых данных. |
| `--chunk-bin <bytes>` | `0` | Переопределяет размер чанка для бинарных данных. | Оптимизировать layout для бинарных данных. |
| `--workers <n>` | `0` | Количество параллельных worker'ов (`0` = default библиотеки). | Ускорить тяжелую перекомпрессию. |
| `--verify-in` | `true` | Проверяет входной контейнер перед pack. | Рано ловить повреждения. |
| `--fast` | `false` | Небезопасный быстрый профиль: отключает CRC-проверку чтения при pack и отключает fsync коммита у выходного файла. | Максимальный throughput на доверенных данных. |
| `--progress` | `true` | Однострочный прогресс pack. | Контроль долгих операций. |
| `--max-entry-size <bytes>` | `0` | Лимит безопасности при чтении/записи. | Защитная перепаковка недоверенных файлов. |
| `--max-chunk-size <bytes>` | `0` | Лимит/проверка размера чанка. | Не обрабатывать слишком большие чанки. |

Оптимизация пропуска:
- Для in-place `pack`, если все чанки уже соответствуют `--codec` и `--level`, не заданы `--chunk-text/--chunk-bin`, и `dead_bytes==0`, CLI выводит `skip` и не переписывает файл.

## `pack-many`
Синтаксис:
```bash
fbx pack-many [flags] <input1.fbx> [input2.fbx ...]
```

Выполняет `pack` параллельно для нескольких контейнеров (всегда in-place для каждого файла).

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--jobs <n>` | `GOMAXPROCS` | Количество файлов, обрабатываемых параллельно. | Масштабировать throughput на многоядерных системах. |
| `--glob <pattern>` | пусто | Добавляет входы по glob (`*.fbx`, `data/*.fbx`). | Пакетный выбор файлов без ручного списка. |
| `--codec store\|zstd\|lz4` | `store` | Кодек перепаковки для всех входов. | Единая политика кодека для набора файлов. |
| `--level <n>` | `0` | Уровень сжатия для всех входов. | Пакетный тюнинг speed/ratio. |
| `--chunk-text <bytes>` | `0` | Переопределение размера чанка для текста. | Единый text chunking в батче. |
| `--chunk-bin <bytes>` | `0` | Переопределение размера чанка для бинарных данных. | Единый binary chunking в батче. |
| `--workers <n>` | `0` | Число worker'ов сжатия на файл. | Тюнинг CPU на один job. |
| `--verify-in` | `true` | Проверяет каждый входной файл перед pack. | Рано ловить повреждения в массовом прогоне. |
| `--fast` | `false` | Небезопасный быстрый профиль на файл (`StrictVerify=false`, `SyncOnCommit=false`). | Максимальный throughput на доверенных данных. |
| `--max-entry-size <bytes>` | `0` | Лимит размера entry на файл. | Ограничение ресурсов в bulk-режиме. |
| `--max-chunk-size <bytes>` | `0` | Лимит размера чанка на файл. | Ограничение декомпрессии/обработки чанков. |

Оптимизация пропуска:
- Для каждого файла, если codec/level уже совпадают, не заданы override размеров чанков, и `dead_bytes==0`, worker выводит `SKIP` и пропускает перепаковку этого файла.

Примеры:
```bash
fbx pack-many --jobs 4 --codec zstd --level 10 --verify-in /data/*.fbx
fbx pack-many --glob '/data/*.fbx' --jobs 6 --codec zstd --level 10 --fast
```

## `add`, `upsert`, `replace`
Синтаксис:
```bash
fbx add [flags] <container.fbx> <source-file>
fbx upsert [flags] <container.fbx> <source-file>
fbx replace [flags] <container.fbx> <source-file>
```

Семантика:
- `add`: ошибка, если запись уже существует.
- `upsert`: добавить или заменить.
- `replace`: ошибка, если записи нет.

Общие флаги (`add`/`upsert`/`replace`):

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--as <entry/path>` | basename source | Путь записи внутри FBX. | Положить файл ровно в нужное место. |
| `--meta-json <json>` | пусто | JSON метаданные прямо в аргументе. | Быстро добавить метаданные из CLI. |
| `--meta-file <file.json>` | пусто | JSON метаданные из файла. | Передавать большие/подготовленные метаданные. |
| `--keep-meta` | `true` | Для `upsert`: если запись уже есть и `--meta-*` не заданы, сохранить существующие метаданные. | Обновить тело записи без потери metadata. |
| `--codec store\|zstd\|lz4` | `store` | Кодек для этой записи. | Точечный контроль сжатия. |
| `--level <n>` | `0` | Уровень сжатия. | Тюнинг zstd/lz4. |
| `--chunk-size <bytes>` | `0` | Форсировать размер чанка для записи. | Переопределить дефолтную политику чанкинга. |
| `--max-entry-size <bytes>` | `0` | Лимит безопасности при открытии. | Защита от oversized данных. |
| `--max-chunk-size <bytes>` | `0` | Лимит/проверка чанка при чтении/записи. | Ограничить обработку чанков. |

Дополнительный флаг `replace`:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--keep-meta` | `true` | Если новые метаданные не переданы, сохраняет текущие метаданные записи. | Заменить контент без потери metadata. |

## `rm`
Синтаксис:
```bash
fbx rm [flags] <container.fbx> [entry ...]
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--prefix <p>` | пусто | Удаляет записи по префиксу пути. | Массово удалить поддерево. |
| `--glob <pattern>` | пусто | Удаляет записи по glob-шаблону. | Очистка по маске. |
| `--contains <s>` | пусто | Удаляет записи, где путь содержит подстроку. | Быстрая «нестрогая» фильтрация. |
| `--min-size <bytes>` | `0` | Удаляет записи с `size >= min-size` (включительно). | Например, удалить только крупные файлы. |
| `--max-size <bytes>` | `0` | Удаляет записи с `size <= max-size` (включительно). | Например, удалить мелкий мусор. |

Логика выбора:
- `[entry ...]`, `--prefix` и `--glob` объединяются по OR (удаляется, если совпало что-то одно).
- `--contains`, `--min-size`, `--max-size` формируют один предикат (AND между заданными условиями).
- Этот предикат тоже объединяется с остальными селекторами по OR.

Пример из вопроса:
```bash
go run ./cmd/fbx rm --contains books/ --min-size 1024 books.fbx
```
Значит: удалить записи, у которых путь содержит `books/` **и** размер не меньше `1024` байт.

## `find`
Синтаксис:
```bash
fbx find [flags] <container.fbx>
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--prefix <p>` | пусто | Оставляет пути с заданным префиксом. | Ограничить поиск пространством имен. |
| `--glob <pattern>` | пусто | Оставляет пути по glob-шаблону. | Фильтрация по маске имени. |
| `--contains <s>` | пусто | Оставляет пути с подстрокой. | Быстрый fuzzy-поиск. |

Логика фильтрации: все заданные фильтры объединяются по AND.

## `stat`
Синтаксис:
```bash
fbx stat [flags] <container.fbx> <entry-path>
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--json` | `false` | Выводит JSON вместо key-value строк. | Удобно для скриптов и парсинга. |
| `--max-entry-size <bytes>` | `0` | Лимит безопасности при открытии контейнера. | Защитный режим чтения. |
| `--max-chunk-size <bytes>` | `0` | Лимит чанка при открытии контейнера. | Защитный режим чтения недоверенных данных. |

Поля вывода: `path`, `size`, `mtime_unix`, `mode`, `flags`, `meta_size` (+ `meta`, если это валидный JSON и включен `--json`).

## `info`
Синтаксис:
```bash
fbx info [flags] <container.fbx>
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--json` | `false` | Полный отчет в JSON. | Автоматический анализ в скриптах. |

Что показывает:
- Количество entries/chunks.
- Сводку по кодекам: `store`, `zstd`, `lz4` или `mixed(...)`.
- Сводку по уровням: один уровень (`0`, `3`, ...) или `mixed(...)`.
- Счетчики чанков по кодекам.
- Счетчики чанков по уровням (`chunks_level_<n>`).
- `dead_bytes`: оценка устаревших байтов, оставшихся после замен/удалений.
- `churn_ops`: число операций replace/remove-типа, создавших устаревшие данные.
- `file_size`: текущий размер контейнера в байтах.

## `set-meta`
Синтаксис:
```bash
fbx set-meta [flags] <container.fbx> <entry-path>
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--meta-json <json>` | пусто | Новые метаданные в JSON-строке. | Быстро обновить metadata в CLI. |
| `--meta-file <file.json>` | пусто | Новые метаданные из файла. | Использовать подготовленный JSON. |
| `--codec store\|zstd\|lz4` | `store` | Кодек для переписанной записи. | Перекодировать запись при обновлении metadata. |
| `--level <n>` | `0` | Уровень сжатия при переписи. | Тюнинг zstd/lz4 по скорости/ratio. |
| `--chunk-size <bytes>` | `0` | Размер чанка для переписанной записи. | Управлять layout переписи. |
| `--max-entry-size <bytes>` | `0` | Лимит безопасности при открытии. | Защитная операция на неизвестных контейнерах. |
| `--max-chunk-size <bytes>` | `0` | Лимит/проверка чанка при чтении/записи. | Избежать oversized chunk processing. |

Важно: `set-meta` переписывает запись целиком (контент читается и пишется снова), это не in-place patch только метаданных.

## `replace-text`
Синтаксис:
```bash
fbx replace-text --find <old> --replace <new> [flags] <container.fbx>
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--find <text>` | обязательно | Искомая байтовая последовательность. | Определить источник замены. |
| `--replace <text>` | пустая строка | Новая байтовая последовательность. | Определить цель замены. |
| `--prefix <p>` | пусто | Ограничение по префиксу пути. | Ограничить область изменения. |
| `--glob <pattern>` | пусто | Ограничение по glob-шаблону. | Точно выбрать подмножество файлов. |
| `--dry-run` | `false` | Только отчет, без записи изменений. | Безопасный предпросмотр. |
| `--codec store\|zstd\|lz4` | `store` | Кодек для переписанных записей. | Сменить кодек при массовой замене. |
| `--level <n>` | `0` | Уровень сжатия для переписи. | Тюнинг zstd/lz4. |
| `--chunk-size <bytes>` | `0` | Размер чанка для переписи. | Управлять итоговым layout. |
| `--max-entry-size <bytes>` | `0` | Лимит безопасности при открытии. | Защитная обработка. |
| `--max-chunk-size <bytes>` | `0` | Лимит/проверка чанка. | Защитная обработка. |

Вывод: `entries_changed=<n> replacements=<m>`.

Важно: замена выполняется как сырая байтовая замена; сейчас команда буферизует каждую подходящую запись в память.

## `verify`
Синтаксис:
```bash
fbx verify [flags] <container.fbx>
```

Флаги:

| Флаг | По умолчанию | Что делает | Зачем использовать |
|---|---:|---|---|
| `--mode dir\|sample\|all` | `dir` | Глубина проверки. | Баланс скорости и полноты контроля. |

Режимы:
- `dir`: только header + directory.
- `sample`: directory + выборочные чанки.
- `all`: directory + все чанки.

Вывод: `entries_checked=<n> chunks_checked=<n> errors=<n>`.
