# Repository Guidelines

## Структура проекта и организация модулей
- `fbx/`: публичный API библиотеки (`Open`, `Create`, `Pack`, ZIP-импорт, транзакции).
- `internal/format/`: бинарные примитивы FBX (header, directory, chunk encode/decode, codecs).
- `internal/pathutil/`: нормализация и валидация путей.
- `cmd/fbx/`: CLI-команды (`convert-zip`, `pack`, `add`, `upsert`, `rm`, `find`, `replace-text`, `list`, `extract`, `verify`).
- `tests/`: интеграционные/совместимость/бенчмарки.
- `tests/testdata/vectors/`: канонические векторы и манифесты для проверок совместимости.
- `docs/`: документация по CLI, API, recovery и процессу разработки.

## Команды сборки, тестов и разработки
- `go build ./...` — собрать библиотеку и CLI.
- `go test ./...` — запустить все тесты.
- `go test -run TestCanonicalVectors ./tests` — только тесты канонических векторов.
- `go test -bench . ./tests` — запустить бенчмарки.
- `go run ./cmd/fbx --help` — посмотреть справку CLI.
- `go run tests/scripts/gen_vectors.go` — пересоздать канонические векторы.

## Стиль кода и соглашения по именам
- Перед коммитом обязательно запускать `gofmt -w`.
- Экспортируемые сущности держать в `fbx/`; внутреннюю реализацию — в `internal/`.
- Следовать соглашениям Go (`CamelCase` для exported, `mixedCaps` для internal).
- Предпочитать потоковый I/O (`io.Reader`/`io.Writer`) для больших наборов данных.
- Сохранять типизированные ошибки (`ErrNotFound`, `ErrCRCMismatch`, `ErrLimitExceeded`) для `errors.Is`.

## Рекомендации по тестированию
- Файлы тестов: `*_test.go`; имена тестов: `TestXxx`; бенчмарков: `BenchmarkXxx`.
- Для каждого исправления добавлять регрессионный тест.
- Для поведения, зависящего от кодека (`zstd`/`lz4`), учитывать доступность кодека.
- Проверять и целостность контейнера (`Verify`), и корректность извлечения.

## Коммиты и Pull Request
- Рекомендуемый стиль: `feat(scope): ...`, `fix(scope): ...`, `docs: ...`, `test: ...`.
- Делать фокусные коммиты (без смешивания рефакторинга и изменения поведения без необходимости).
- В PR указывать: цель, затронутые разделы RFC, команды валидации и CLI-примеры для UX-изменений.

## Безопасность и конфигурация
- Рассматривать входные FBX/ZIP как недоверенные данные.
- Использовать `--max-entry-size` / `--max-chunk-size` (CLI) и `Options` (API) для ограничения ресурсов.
- Не коммитить артефакты большого размера (`*.fbx`, распакованные корпуса, временные файлы).
